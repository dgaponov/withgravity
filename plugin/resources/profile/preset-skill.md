# Пресет проекта — профиль сервиса, подключаемый как скилл

Пресет — обычный скилл, в папке которого лежит `service-profile.json`. Подключить «как принято у нас» к проекту — значит
установить этот скилл; плагин и официальный скилл при этом остаются общими и ничего о сервисе не знают. У каждого проекта свой
пресет; один пресет может обслуживать несколько проектов команды.

## Состав
```
<имя>-gravity-preset/
  SKILL.md               # frontmatter + короткая инструкция (шаблон ниже)
  service-profile.json   # обязателен; схема и валидатор — рядом с этим файлом
  theme/                 # по необходимости: файлы, на которые ссылается theme.themeConfig
  templates/             # по необходимости: шаблоны, на которые ссылается профиль
  libraries/             # по необходимости: паспорта библиотек сервиса
```
Признак пресета — файл `service-profile.json` в корне папки скилла. Пути в профиле — относительно папки скилла.

## Где искать (первое найденное закрывает вопрос о профиле)
1. `service-profile.json` в проекте — профиль уже выбран раньше.
2. Пресет, названный в инструкциях проекта (`AGENTS.md` / `CLAUDE.md`: «Gravity-пресет: `<имя скилла>`») или в брифе.
3. Скиллы проекта: `.claude/skills/*/service-profile.json`. Один — берётся без вопроса; несколько — вопрос с опцией на каждый.
4. Скиллы пользователя (`~/.claude/skills/*/service-profile.json`) и скиллы установленных плагинов — только кандидаты: показываются
   опциями в вопросе о профиле рядом с «без профиля», сами не применяются (у пользователя могут стоять пресеты других проектов).
5. Пакет команды с `pack.json` рядом — как раньше.

Папка `.claude/` в репозитории может быть в игноре системы контроля версий — тогда пресет доставляется установкой скилла
(стор скиллов, `npx skills add`, плагин команды), а в инструкциях проекта остаётся строка из п. 2.

## Как применять
Пресет применяется на месте: профиль читается из папки скилла, в проект не копируется (исключение — выбранный вариант темы, он
сохраняется в проекте, как у профиля из пакета). Тема — копией в `src/theme/`, как у любого профиля. Остальное —
`README.md` рядом. В сдаче источник — «пресет <имя скилла>» и его `version`.

Пресет меняет только владелец: правило сервиса, найденное при сборке, идёт в `proposals.json`, а в пресет — через `profile`
по поручению.

## Готовое руководство вместо своих правил
Если у компании уже есть скилл или документ с правилами интерфейсов, пресет его не пересказывает, а ссылается: `guides[]` в
профиле (`ref`: путь в папке пресета или `skill:<имя>`; `when`; `deviations` — где сервис отступает и почему). Так один общий
скилл обслуживает много проектов, а пресет проекта остаётся коротким: выбор темы, раскладки и список отступлений.

## Что остаётся вне пресета и вне плагина
В пресете — правила и тема сервиса. Корректность компонентов — официальный скилл; общие конвенции — плагин. Имена внутренних
пакетов, адреса, названия продуктов и людей в плагин не попадают: им место в пресете (`libraries`, `approvedComponents.preferred`,
`glossary`).

## Шаблон SKILL.md
```markdown
---
name: <имя>-gravity-preset
description: >-
  Пресет «как принято у нас» для Gravity UI в <сервис>: тема, плотность, раскладка, политики форм, выбор компонентов.
  Применяется плагином withgravity; используй при любой сборке или правке интерфейса <сервис>.
---
# <сервис>: пресет Gravity UI

Правила — в `service-profile.json` рядом. Сборку веди скиллом `withgravity:build`: он найдёт этот пресет сам. Плагина нет —
прочитай профиль как требования к интерфейсу и следуй официальному скиллу `gravity-ui`.
```
